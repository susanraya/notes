<!-- sdlc:auto:start overview -->
notes is a two-part application generated by the Quorq AI SDLC platform: a React 19 + Vite single-page frontend that renders fully-approved screens against seeded sample data, and a FastAPI 0.115 backend that currently exposes only a health check and a seeded sign-in/auth flow, with every other endpoint scaffolded as a typed stub awaiting an approved architecture. The backend persists to PostgreSQL in production (SQLite by default locally) via SQLAlchemy models and Alembic migrations that run automatically on startup, and the frontend talks to it through a generated openapi-fetch client.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js and npm (for the Vite/React 19 frontend)
- Python 3.12 (matches backend/Dockerfile)
- pip
- Docker and Docker Compose (for the local PostgreSQL service in docker-compose.yml)
- PostgreSQL 16 (via docker-compose, required for backend pytest and for the Playwright/e2e-covered API behaviour)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository.
2. Copy .env.example to .env and fill in any values it requires.
3. Backend: cd backend && pip install -r requirements.txt
4. (Optional, for Postgres-backed work) from the repo root run: docker-compose up -d db
5. (Optional) set DATABASE_URL to point at that database, e.g. postgresql+psycopg://app:<database-password>@localhost:5432/app -- otherwise the backend defaults to a local sqlite:///./app.db file
6. Start the backend: cd backend && uvicorn app.main:app --reload (this applies Alembic migrations and seeds users on startup)
7. Frontend: cd frontend && npm install
8. Start the frontend: npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend API models extend ApiModel (app/api_model.py) so JSON fields are camelCase.
- One SQLAlchemy model class per entity in app/models.py; schema changes go through Alembic migrations in backend/alembic/versions/, never SQLAlchemy create_all.
- One router per architecture component that owns endpoints, registered in app/main.py; unimplemented endpoints return a typed StubResponse rather than erroring.
- Database session is request-scoped via the get_db dependency in app/database.py.
- Frontend screens are generated modules under consumption of a shared UI/icon vocabulary (src/lib/ui.tsx, src/lib/icons.tsx) and call the backend only through the generated client in src/api/client.ts.
- Vitest component tests live beside the components they cover and are scoped to src/**/*.{test,spec}.{ts,tsx}; Playwright specs live in e2e/ and match *.spec.ts.
- All test runs (pytest, Vitest, Playwright) write JUnit XML to a fixed reports/junit/ folder for the platform's test reporting.
- Backend linting/formatting uses ruff (ruff.toml); frontend uses ESLint (eslint.config.js) and Prettier (.prettierrc).
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend calls to the backend fail with a CORS error. | Set ALLOWED_ORIGINS (comma-separated origins) as an env var for the backend; it defaults to the Vite dev server origins only (http://localhost:5173 / http://127.0.0.1:5173). |
| Backend fails to start with an error about alembic.ini being missing. | Run the app from a checkout that still has backend/alembic.ini and backend/alembic/ beside backend/app/ -- the Dockerfile copies both into the image and app/main.py requires them to apply migrations on startup. |
| pytest fails or cannot find a database. | Point DATABASE_URL at a running PostgreSQL instance (e.g. via docker-compose up -d db) as described in TESTING.md; the default SQLite file is for local dev only, not the test suite. |
| npm run build succeeds but the app is broken at runtime or tsc fails separately. | Run npm run typecheck -- npm run build does not typecheck, so type errors can pass build but should be fixed before relying on the code. |
| Playwright e2e run can't start the backend. | Ensure backend dependencies are installed into backend/.venv (playwright.config.ts invokes backend/.venv/bin/python) before running npm run test:e2e. |
<!-- sdlc:auto:end troubleshooting -->
